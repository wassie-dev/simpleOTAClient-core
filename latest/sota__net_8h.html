Detailed Description

HTTP, implemented by the platform port (esp_http_client on ESP32, for both clients) and by the host tests' fake.

user is the sota_config_t's user pointer, where the port keeps its TLS settings. TLS trust is entirely the port's.

POST body as JSON to url, with "Authorization: Bearer <token>".

One attempt: the engine retries. Returns the HTTP status, or -1 when no response came back. When resp is not NULL it gets up to cap - 1 bytes of the response body, NUL-terminated.

Start a firmware download: a GET without the Authorization header (the pre-signed URL carries its own credentials).

Returns the HTTP status, or 0 when no connection was made. On 200, *len is the Content-Length or -1; on anything else the download is already closed.

Redirects are not followed here: the engine checks where each one leads. On a redirect status, location gets the Location header, NUL-terminated, or an empty string when there is none or it does not fit location_cap.

Read the next bytes of the body: a count, 0 once the whole body has arrived, SOTA_NET_AGAIN, or SOTA_NET_ERROR.
